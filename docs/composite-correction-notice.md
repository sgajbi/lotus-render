financial values, units, display policies, nulls, reason codes, source captures and row populations

The path is O → O_rr → C → C_rr. Wire transitions named `correct` do not classify economic
changes. The two economic anchors are the exact node0/O and node2/C records. Each own-custody
binding retains the original job/snapshot/revision/hash tuple and adds the exact source document

JSON is not a current authority grant.

The r6 economic edge uses `ARCHIVE_RELATIONSHIP_RECORD`, with exactly lifecycle relationship ID,
source/target document IDs, transition type/reason/reason code, requester and aware timestamp.
It cannot contain `current_document_id` or claim recovery of the original POST response. Technical
edges keep complete Report lineage events. Strict native record semantics supplement JSON Schema
format checks, whose optional date-time support varies by installed validator environment.
The exact supplier schema embeds Archive's native DTO, while Render's existing typed profile
continues to cap relationship and document identifiers at 256 characters. Native DTO acceptance
alone cannot expand that profile or admit a naive timestamp. Validation preserves captured strings,
including aware non-UTC offsets, rather than rewriting them as new evidence.

## Workbook and limits

The workbook retains 28 side tables plus NoticeScope, PairIndex, ArchivePath and
Obligations. CellEvidence adds six provenance columns to the existing seven, with one row for
every semantic cell. ColumnPolicy retains all column policies. ArtifactIdentity appends six
bound notice/generation values; PinnedData retains the complete canonical dataset. Financial
display still uses the existing declared conversion and rounding, with literal text storage.

Every actual repetition of source identity in context, metadata, envelope and physical identity
fragments consumes the existing aggregate budget. The planner counts 1000 data rows per sheet
plus a header and 30000 aggregate data rows, all repeated header cells/text, identity fragments,
PinnedData, partitions and output bytes. No cap increases, per-side budgets, truncation or source
omission are permitted. The exact native package measures 4,824,578 request bytes, 47 sheets,
12,777 data rows, 150,148 physical cells and 7,746,370 text bytes. The actual pinned writer produces
890,817 bytes, below the unchanged 16 MiB output cap. Independent OOXML decoding reconciles every
physical cell, partition, visible display and PinnedData roundtrip. Bounded fingerprint:
`89bdd847cd33ebceebeb8127039e79909627828f72a05ef7f5c8b5c22ccdfab1`.

All 35 other logical tables equal the native producer plan. Its ArtifactIdentity contains a
placeholder template digest and different rounding description/order. Render retains its existing
identity fields/text/order, supplies the actual layout digest and appends the exact six notice
fields. This accounts for seven fewer text bytes than the producer planner. ZIP custody SHA names
actual bytes; bounded determinism compares package member payloads rather than container metadata.
